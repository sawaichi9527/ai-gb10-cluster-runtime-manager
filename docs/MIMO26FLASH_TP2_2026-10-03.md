# MiMo V2.6 Flash MOPD on TP2 — deployment + benchmark (2026-10-03)

New cluster lane **`mimo26flash`**: Xiaomi MiMo-V2.6-Flash-**MOPD** served on the
2-node DGX Spark (GB10, sm_121) TP2 cluster with vLLM + the checkpoint's bundled
DFlash drafter. Cluster-only and exclusive (like `deepseek`); serves the unified
`:1234` OpenAI API as model id **`aeon`**, 256K context, 8-way concurrency.

## 1. Lineage and artifacts

- Recipe: `tonyd2wild/MiMo-V2.6-Flash-DGX-Spark-Recipe` (MIT, commit `13621bb3`).
  vLLM TP2 + DFlash on 2x GB10.
- Image: `ghcr.io/tonyd2wild/vllm-glm53-flash:sm121-v11-dflash2`
  (community image; vLLM `0.1.dev20051+g487ecf187`, torch 2.13, CUDA 13, sm_120).
  Manifest digest `sha256:4def0ef644cb2e9814136dcffd5e385e21bc594f48f3b292234051904abe85a6`.
- Weights: `XiaomiMiMo/MiMo-V2.6-Flash-MOPD` (official MXFP4 QAT), revision
  `2479e2d0029eca9a34cc7e7f55a121925f81908e`, ~166G (154 files, `SHA256SUMS`).
  On both nodes at `$HOME/docker-stacks/models/mimo-v2.6-flash-mopd`.
- Runtime support vendored at `patches/mimo26flash/` (3 patched vLLM sources +
  repaired dflash config; see its `NOTICE.md`), bind-mounted read-only.

### Ship notes

- **Model download** (node0, then rsync to node1 over CX7 at ~350 MB/s): the HF
  download ran 5h34m at ~8-9 MB/s and completed cleanly. `SHA256SUMS` (154 lines)
  was generated locally; 4 files cross-checked against HF LFS sha256 — all match.
- **Image pull**: GHCR/CDN became unusable from this site mid-transfer (~0.1-0.5
  MB/s, repeated `unexpected EOF` on the two largest layers; docker does not
  resume a partial layer, so it looped). Resolved by pulling the *same* image via
  the anonymous mirror **`ghcr.nju.edu.cn`** (~2-5 MB/s, range-capable), verified
  byte-identical by manifest digest, then `docker tag` to the ghcr.io name on both
  nodes. `IMG_SHA256` pins the digest; the image gate passes (it matches the
  digest value in `RepoDigests`).

## 2. Profile (`cluster-profiles.d/mimo26flash.conf`)

| field | value |
|---|---|
| `STACK_DIR` / `COMPOSE_FILE` | `~/docker-stacks/tonyd2wild-vllm-mimo26flash` / `docker-compose.mimo26flash.yml` |
| `BODY_REL` | `mimo-v2.6-flash-mopd` (drafter inside the checkpoint at `/model/dflash`) |
| `MAXLEN` / `NUMSEQ` / `GMU` | 262144 / 8 / **0.90** (recipe value) |
| `KV_DTYPE` / `MOE_BACKEND` / `LINEAR_BACKEND` | `fp8` / `marlin` / `auto` |
| `DISABLE_CUSTOM_ALL_REDUCE` | `false` (recipe keeps custom all-reduce) |
| `SPEC_CONFIG` | `{"method":"dflash","model":"/model/dflash","num_speculative_tokens":7}` |
| parsers | `mimo` / `mimo`, auto-tool-choice on |
| `BATCHED` / chunked-prefill / prefix-caching | **unset** → loader emits none of them; vLLM defaults apply (`enable_prefix_caching=True, enable_chunked_prefill=True`), exactly the recipe launch |
| `EXTRA_ENV` | `VLLM_USE_DEEP_GEMM=0` (SM12x DeepGEMM corrupts fp8 GEMM), `TORCH_CUDA_ARCH_LIST=12.1a`, offline HFs, RoCE/NCCL |
| `EXTRA_ARGS` | `--distributed-executor-backend mp`, `--no-async-scheduling`, `--generation-config auto`, `--override-generation-config {"repetition_penalty":1.05}`, `--default-chat-template-kwargs {"enable_thinking":false}` |
| `SYNC_DIRS` | `patches/mimo26flash` → `$STACK_DIR/patches` on both nodes |
| `AUTOTUNE_CACHE_REL` | `.cache/vllm-mimo26flash/flashinfer_autotune_cache` |

`scripts/cluster-common.sh` was extended so `BATCHED`, `ENABLE_CHUNKED_PREFILL`
and prefix caching are **omitted when a profile leaves them unset**. All existing
profiles set them, so their rendered argv is byte-identical (verified: old-vs-new
render IDENTICAL for 27b/35b/deepseek/deepseek-vision/qwen38flash).

## 4. Benchmarks (2026-10-03, live `mimo26flash`, one session, same TP2)

### `scripts/bench-c.sh` — 400 max_tokens

Fixed-length (`BENCH_IGNORE_EOS=1`, exactly 400 tok/stream):

| C | aggregate tok/s | acceptance | mean accept len |
|---|---|---|---|
| 1 | 21.1 | 11.9% | 0.83 |
| 2 | 33.9 | 19.2% | 1.34 |
| 4 | 49.1 | 20.1% | 1.41 |
| 8 | **67.9** | 17.5% | 1.22 |

Default sampling (streams stop early):

| C | aggregate tok/s | mean accept len |
|---|---|---|
| 1 | 24.0 | 1.55 |
| 2 | 29.2 | 1.63 |
| 4 | 49.5 | 1.69 |
| 8 | 66.6 | 1.47 |

Acceptance is low vs tonyd2wild's tuned 9-category prompt set (they report ~5.2/7
on code), because `bench-c` uses the repo's generic prompt at the checkpoint's
default sampling (temperature 1.0). Expect materially higher aggregate on
code/structured traffic.
